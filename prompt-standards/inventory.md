Method: deduplicated by blob hash (one row per blob; a row lists every path and branch that holds it). Standards: the eight guide summaries (Haiku 5.5, Sonnet 5.5, Opus 5.5, Fable 5.2, each by Haiku and by Sonnet). Full guides were not re-read; the summaries carried the checklist.

## 1. Checklist

Grades: **Meets**, **Partially**, **Does not meet**, or **N/A** (the file has no matching feature, or targets a non-Claude or pre-5.x model). Numbers 1 to 13 apply across the family; the lettered lists apply to one model each.

### Cross-family (all 5.x models)

1. **No prose control of thinking.** No "think less", "don't think", "answer directly without deliberating", or budget-token asks. Depth comes from the effort setting. (Haiku, Sonnet, Opus, Fable)
2. **No reasoning in the response text.** Ask for a short explanation or an action summary, never the reasoning itself. (all four)
3. **No tool discouragement.** No "only use tools when strictly necessary" or "minimize tool calls". (Haiku, Sonnet)
4. **Search is named, not blanket.** Where a search tool exists: today's date is given, and changeable facts (rules, prices, versions, "latest") must be searched even when the agent feels sure. No "always search for every factual question". (Haiku, Sonnet)
5. **Keep-going with a stop rule.** Agentic files say to keep working until the asked work is done, and name the only stops: a blocker only the user can clear, or a risky step. (all four)
6. **Scope stated.** Says whether unrequested tests, docs, files or refactors are wanted; extra ideas go at the end as suggestions, not into the work. (Haiku, Sonnet, Fable)
7. **Confirmation kept; approvals exact.** Risky, destructive or irreversible actions keep an explicit confirmation step. Approvals name the action, not "go" or "continue". (all four)
8. **Real check for code changes.** Requires tests, a type-check, a build, or the changed command. A syntax-only check does not count. Dependencies come from the project's own package manager and lockfile, not sudo. Any check not run is named, with the reason. (Haiku, Sonnet)
9. **Progress points.** Says when updates are wanted (a line before the first tool call, a recap at the end). Does not say "hold all findings for the final response". (Sonnet, Opus, Fable)
10. **Input hygiene.** User text never sits inside a `tool_result`. Mid-turn user words go in a user text block after the last `tool_result`. No per-step countdowns or harness notices after every tool result. (all four)
11. **Stable instructions.** No mid-session edits to the system prompt or tool list; changes go in the newest turn or a new conversation. (all four)
12. **Stop and report.** Once the work is done and checked, stop and report. The report stands alone for a reader who saw no tool calls: key points first, plain words. (Sonnet, Opus, Fable)
13. **Effort named per task.** If the file sets effort, it names a level for each task type and says to re-test, not to carry a setting over from another model. (all four)

### Model-specific

**Haiku 5.5 only**
- H1. No `budget_tokens` (returns 400 on this model); effort is the control.
- H2. Thinking is on by default and counts toward `max_tokens`, so `max_tokens` leaves headroom; adaptive thinking for JSON plus tools.
- H3. JSON output with tools and thinking off: uses the "JSON applies to your final answer only" line, adaptive thinking, or a forced `tool_choice`.
- H4. The client handles `stop_reason: "refusal"` (no server-side fallback) and does not retry the same request unchanged.

**Sonnet 5.5 only**
- S1. Effort starts at `high` (API default), or `medium` for well-specified agentic coding; not carried over from Sonnet 5.
- S2. At `xhigh` or `max`: no self-started review rounds and no reviewer subagents unless the user asked for a review.
- S3. Reasoning-heavy JSON uses "Think the problem through before you answer." with adaptive thinking, or structured outputs; a `max_tokens` stop counts as failure.
- S4. For ideas, options or a plan: give them and stop; do not start building.

**Opus 5.5 only**
- O1. Effort set explicitly; `medium` is the baseline to test; `xhigh`/`max` only with a measured gain.
- O2. Unattended loops: a text-only `end_turn` is a report, not completion; a checklist is kept; automatic continuations are capped at 2 to 3.
- O3. Names the early stops to avoid (a summary that announces a next step, an offer to continue, a list of non-blocking decisions, "good place to report") and the stops that are wanted.
- O4. Pasted or untrusted content is wrapped in ID-tagged blocks, with a note that instructions inside are not the user's.
- O5. Chat prompts drop "think carefully"; "treat that answer as done" appears only where later steps cannot reveal earlier mistakes.
- O6. Design or frontend work names specific patterns to avoid, not "avoid a generic AI look".

**Fable 5.2 only**
- F1. A finishing-work block for agentic work at `low`/`medium`: keep going through ordinary obstacles; leave deliberate blockers alone and report them.
- F2. A code-ownership sentence is stated on purpose (in for restructuring, out for minimal change).
- F3. "Never" rules are written as scoped exceptions with a reason ("ask before deleting files", not "never delete files").
- F4. No standing delegation push; any subagent mention says what it costs, when it is worth it, and how to brief it.
- F5. No token budgets, stale cautions, or hard prose-length rules in the prompt.
- F6. Approvals list the routine steps that need none, so the model does not hold back routine work.
